# Project Rules (Masarrah — مسرة للاستقدام)

## Tailwind CSS v4 — modern variable-first configuration

- Design tokens live ONLY in `app/globals.css` as CSS variables: the raw values in `:root`, exposed to utilities through `@theme inline` (Tailwind v4 CSS-first config). There is no `tailwind.config.js`.
- Consume tokens exclusively through utility classes generated by `@theme inline`: `bg-embassy`, `text-court-gold`, `text-champagne-gilt`, `font-headline`, `text-label`, `text-title`, `text-body`, `rounded-md`, `shadow-float`, `gap-md`, `px-sm`, etc. Never hardcode hex values or font stacks in components; use the token utilities.
- Custom spacing (`--spacing-*`), typography (`--text-*`), fonts (`--font-*`), radii (`--radius-*`), shadows (`--shadow-*`), and colors (`--color-*`) are all consumed as generated classes — e.g. `px-md`, `text-label`, `font-body`, `rounded-lg`, `shadow-float`, `bg-chancery`.
- RTL is the substrate: use logical properties (`ms-*`, `me-*`, `ps-*`, `pe-*`, `text-start`) and `gap-*` so Arabic (default, RTL) and English (LTR) mirror correctly. Never hand-build a separate LTR layout.
- Respect `prefers-reduced-motion`: framer-motion animations must be gated with `useReducedMotion()` where motion is not essential (scroll-linked hide/show).

## i18n — translations + locale

- All user-facing copy lives in `app/translations/en.json` and `app/translations/ar.json`. Never hardcode strings in components.
- Read copy with the typed hook from `@/app/hooks/useTranslations`:
  `const t = useTranslation("object-key")` → then `t.title`, `t.nav.primaryButton`, `t.contact.call`, etc. Keys are nested under a top-level object key (e.g. `header`, `footer`).
- Locale is client state in `@/app/hooks/useLocale`: `useLocale()` returns `"ar" | "en"`, `setLocale("ar" | "en")` switches language and sets `<html lang dir>` (Arabic is the default and RTL; English is LTR). `initLocale()` applies the stored locale on mount.
- Contact details (phone, WhatsApp, email, address) are centralised in `app/config/site.ts` as placeholders — replace with confirmed values before launch.
- Bilingual parity: no page or component ships in only one language.

## Layout chrome

- Root layout renders `<SiteHeader />` and `<SiteFooter />` (`app/components/layout/`) around `<main className="flex-1 pt-20">` — the fixed header is 80px (h-20), so main content offsets by `pt-20`.
- The header hides on scroll down and reveals on scroll up (framer-motion `useScroll` + `useMotionValueEvent`), with the mobile drawer and language toggle always reachable.
